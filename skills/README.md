# Initial skill catalog

TPM-OS Phase 1 contains exactly five professional skills.

A skill performs a discrete job for a TPM. It must be independently useful and must not require the user to adopt a prescribed assistant, toolchain, or management style.

## The five skills

| ID | Skill | Professional job | Status |
| --- | --- | --- | --- |
| SKILL-001 | Session Bootstrap | Establish the context, evidence, constraints, unknowns, and objective for the current working session. | Planned |
| SKILL-002 | Program Bootstrap | Turn an ambiguous program into a structured starting point, identify gaps, and recommend first actions. | Planned |
| SKILL-003 | OKR Builder | Develop measurable, outcome-oriented objectives and key results from the available strategy and evidence. | Planned |
| SKILL-004 | Stakeholder Mapper | Identify stakeholders, influence, decision rights, communication needs, and relationship gaps. | Planned |
| SKILL-005 | Executive Review Builder | Build an executive-ready narrative and anticipate the questions leadership is likely to ask. | Planned |

No additional skills are in the current product scope.

## Skill contract

Each skill specification will define:

1. **Purpose** — The single professional job the skill performs
2. **User and invocation** — Who uses it and when
3. **Required inputs** — Evidence needed to run responsibly
4. **Optional inputs** — Context that can improve the result
5. **Unknowns and assumptions** — What is missing or inferred
6. **Workflow** — The repeatable sequence of work
7. **Deterministic steps** — Calculations, transformations, and checks performed without AI
8. **Reasoning steps** — Tasks requiring ambiguity resolution, synthesis, judgment, or communication
9. **Output contract** — The structure and meaning of the result
10. **Validation** — Checks applied before presenting the result
11. **Human review** — Decisions or claims requiring TPM approval
12. **Failure modes** — Conditions under which the skill should stop, qualify, or refuse
13. **Evaluation cases** — Representative scenarios and expected quality criteria
14. **Examples** — Realistic inputs and outputs without proprietary information
15. **Version** — A record of changes and the evidence behind them

## Battle-hardening gate

A skill progresses through these states:

1. **Planned** — The job and scope are named
2. **Specified** — The complete skill contract is documented
3. **Prototype** — The workflow can be exercised end to end
4. **Evaluation** — Representative cases are scored against explicit criteria
5. **Field test** — Practicing TPMs use the skill in real scenarios
6. **Battle-hardened** — Failures and feedback have produced demonstrable improvements

No skill will be described as battle-hardened until it has passed every stage.

## Scope discipline

Ideas for additional skills may be recorded as research, but they will not enter the product catalog until the first five satisfy the battle-hardening gate.
